# Post-Mortem Reports

This directory serves as the designated location for documenting significant efforts and insights gained during the development process. Before merging a feature or debug branch back into the `development` branch (or immediately following a substantial inter-branch effort), a report detailing the work undertaken, its rationale, methodology, and lessons learned should be placed here.

## Purpose of a Post-Mortem Report

A post-mortem report should provide a comprehensive overview of a development effort, covering:
-   **What was done**: A clear description of the tasks completed and features implemented.
-   **Why it was done**: The problem addressed, the goals, and the intended impact.
-   **How it was done**: The technical approach, tools used, and key decisions made.
-   **What was learned**: Insights gained, unexpected challenges, successful strategies, and areas for future improvement.
-   **Impact Assessment**: A brief evaluation of the changes' performance, stability, and adherence to design goals.

## Naming Convention
Files must follow the chronological prefix standard:
`YYYY-MM-DD_snake_case_description.md`

This ensures chronological sorting and clear context in the file system.
