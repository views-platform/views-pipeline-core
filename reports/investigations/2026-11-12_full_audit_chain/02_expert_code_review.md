# 2. Expert code review — views-pipeline-core (2026-11-12)

Starting context: the assimilation report (01) plus targeted reads this session. Every observation names a file; where a finding is already in the register it is cited by ID rather than restated.

## 1. System summary

views-pipeline-core is the orchestration library every VIEWS forecasting engine subclasses. A generated `main.py` builds a `ForecastingModelManager` subclass, which fetches and caches input data, calls the engine's train/evaluate/forecast hooks, validates and persists predictions to local disk, views-forecasts and Appwrite, scores them with views-evaluation, and hands reports to views-reporting. Three ensemble managers (one inheriting, two composing) run member models as subprocesses, pool their outputs, reconcile grid to country through an injected port, and publish pooled draws to the FAO wire. The package is 29k lines of source held by a 50k-line test suite and 40k lines of governance prose; it is in its third major and mid-migration from a pandas object-cell prediction tier to the `views_frames.PredictionFrame` leaf.

## 2. Expert reviews

### Robert C. Martin — Clean Code / Clean Architecture
**Strengths.** The ADR-045 stage extraction is real: `managers/{training,forecasting,evaluation,reporting}/stage.py` take frozen contexts (`types.py:73-85`) and do not reach back into the facade. The reconciliation seam is a textbook DIP port (`domain/reconciliation_port.py`) injected at the composition root, and `tests/test_boundary_enforcement.py` turns ADR-002's directory rules into AST checks. `modules/dataloaders/fetch_context.py` and `provenance_builder.py` show the house style at its best: pure resolution, one write-back site, a record that says what it is.
**Weaknesses.** `ForecastingModelManager` is still 1,724 lines and 32 methods with 26 internal imports placed inside function bodies to dodge cycles (C-01, C-47); `_execute_model_evaluation` alone is 256 lines (C-34). `files/utils.py` is the catch-all the design preferences forbid, with the highest fan-in in the package (C-58). The `domain/` layer exists but ADR-002 does not place it, and nothing in the package imports `horizon.py`, `temporal.py` or `reconciliation_invariants.py` — a domain layer with no consumer is a diagram, not a boundary (C-38). Dispatch by class-name string (`model_path.py:479`) and by `target`/`prediction_format` literals is the opposite of the Dependency Rule: the base class knows its subclasses by name (C-348).
**Improvements.** Finish D-04: move `ModelPathManager` behind `ModelPathProtocol` and make `EnsemblePathManager` satisfy it (today it does not even carry `data_raw`, C-341). Give `domain/` an ADR and one real consumer (S-06 wiring the sniffer to `PartitionSet`/`ForecastHorizon`) or delete it. Split `files/utils.py` into `files/logs.py`, `files/parquet.py`, `files/names.py` — three reasons to change.

### Gang of Four — Design patterns
**Strengths.** `PredictionSaver` is a clean Strategy with three interchangeable implementations composed in order (`model.py:602-616`). `Reconciler` is a Port/Adapter pair done once and reused by both tiers (`modules/reconciliation/adapter.py`, `reconcile_frames.py`). `lazy_attach` (`_lazy.py`) is a small, correct Facade over PEP 562.
**Weaknesses.** `DataFetchStrategy` (`types.py:95`) is a Strategy declared and never implemented or dispatched; `ViewsDataLoader._fetch_data` dispatches on the `source` string instead (C-164). `EnsembleManager` is a Template Method subclass that overrides the hooks with different signatures (`ensemble.py:413,428` vs `model.py:675`), which is why D-03/D-13 keep returning. `NpzSaver` and `_save_via_io_manager` are strategies no production path selects — dead branches that look like options. The `wandb` lifecycle (`with initialize_run: try/except/finally finish_run`) is repeated in eleven methods across four files; D-06 resolved to extract it "with E3" and E3 shipped without it.
**Improvements.** Either wire `DataFetchStrategy` (three implementations exist as `_fetch_data_from_*`) or delete the Protocol. Extract the wandb run lifecycle into a context manager that takes the stage name and the exception class — eleven sites become one.

### Michael Feathers — Legacy code & safe change
**Strengths.** The characterization layer is thick where it was planned (D-05: 10 characterization tests on `_execute_model_evaluation`; `tests/test_modules/test_dataloader_characterization.py`; `test_ensemble_context_characterization.py`). `conftest` fixtures for provenance let the cache seam be tested with real files. The streaming evaluation test (`test_streaming_evaluation.py`) is the one place the facade runs unmocked, and it is real.
**Weaknesses.** Safety ratings: `modules/validation/*`, `domain/`, `managers/prediction/*`, `modules/aggregation` — safe to change. The three ensemble managers and the facade — risky: their suites are 90-120 mock lines each with assertions mostly of the `assert_called` kind, so a refactor that preserves call shapes but changes behaviour passes. `data/handlers.py` (947 lines, 17 asserts) — dangerous; its zero-fill (C-364) has no characterization test at all. `validation/ensemble/check.py` constructs an `EnsembleManager` inside a validator (C-50) so every test of it must mock the manager hierarchy. `files/utils.py::handle_ensemble_log_creation` has zero execution coverage (C-310, C-371).
**Improvements.** Before C-36's decomposition, write the characterization tests for `_preprocess_dataframe` that pin the fill and the `np.resize` padding — then decide whether to keep them. Replace the `assert_called` assertions on the ensemble managers with output assertions on a two-member fixture (`test_ensemble_sample_count_guard.py` shows the shape).

### Michael T. Nygard — Production reliability
**Strengths.** Appwrite HTTP calls are bounded (`transport.py`, env-configurable, idempotent install). Member subprocesses have a 7,200 s timeout. The wire publisher is manifest-last so a killed run leaves nothing a consumer will read (`sampled_forecast_publisher.py`). ADR-047 states the destination hierarchy and the code follows it: views-forecasts failure is fatal, Appwrite failure is logged.
**Weaknesses.** `get_latest_release_version_from_github` runs `git ls-remote` via `shell=True` with no timeout, then an unauthenticated GitHub API call with no timeout, at manager construction when the store is on (C-57); it also picks the wrong tag once a component reaches 10 (C-366). The wire publisher uploads shards sequentially with no retry and no idempotency key: a transient fault on shard 30 of 36 aborts and leaves 29 orphan shards that only the shelf audit will find (documented, but the audit is manual). `LoggingModule` reconfigures root logging for the whole process at construction and swallows its own failure into `basicConfig` (`logging.py:59-75`). WandB telemetry failures are swallowed at five sites, so a run can lose its metrics table and still alert success. Evaluation can complete with no metrics (C-362). The ensemble validator reads artifact-time logs rather than live configs (C-215).
**Improvements.** One `timeout=` on both network calls in `package.py` and a cached result per process. For the publisher, record the shard list before uploading and make a re-run skip shards whose hash the store already holds (the store dedups on hash + name since #551, so this is mostly a resume loop). Treat "no actuals" as a raise, not a return.

### Martin Kleppmann — Data systems & correctness
**Strengths.** Cache provenance (ADR-059) is a proper identity record: identifying fields vs recorded fields, versioned, refused on mismatch, refetched on absence. The PF pool refuses row, identifier and sample-count mismatches and names the differing values. The frame cache writes stage-then-swap.
**Weaknesses.** The MetricFrame path has no run identity, so every evaluation overwrites the last and a skipped evaluation leaves a stale evaluation-of-record (C-362; `run_id` is inside the frame but not in its path). `_ViewsDataset` manufactures zeros for missing cells and repeats samples with `np.resize` (C-364). Weighted pooling degrades to equal weights on a key mismatch (C-363). The adapter's compound key is only injective while predicted units are bounded by the actuals' maximum (C-365). "Latest" artifact, prediction and cache are all chosen by lexical filename sort, and a named artifact bypasses the timestamp regex entirely (`model_path.py:808-815`). The DF `concat` pool resamples with a fixed seed while the PF `concat` stacks every draw — one config word, two sample semantics. The pandas parquet cache writes non-atomically (C-211).
**Improvements.** Put `run_id` (or the artifact timestamp) in the MetricFrame directory and have `PerModelMetricFrameSource` refuse a frame whose provenance predates the run it reports. Make `_normalize_weights_new` refuse when `use_weights` is true and any requested name is absent from the config map — the refusal already exists and is unreachable.

### John Ousterhout — Complexity management
**Strengths.** `ViewsDataLoader.get_data` hides a lot behind one call: context resolution, provenance, fetch dispatch, sniffing — a deep module. `CoreConfigSniffer.sniff_all` is the single entry for config validation and every manager calls it. `PredictionStoreConfig.from_environment` fails loud on every missing variable at once.
**Weaknesses.** The facade leaks: engines must know `_get_cached_data_path`, `_reference_entities`, `prepare_actuals_df`, the `configs` fresh-dict semantics and the timestamp copy-back convention (C-350, and the template teaches the no-op form of it — C-375). `configs` returning a new dict on every access is a trap with a setter that looks like item assignment but is not; the ADR warns against the trap in prose. Two prediction tiers, two ensemble managers for the same tier, two Appwrite metadata builders (C-352), two frame-load boundaries (C-212), two cache-write semantics (C-211) — the migration doubled the surface and the retirements have not caught up. The register's own `Last updated` line is a 6,000-word changelog a newcomer must scroll past.
**Improvements.** Freeze `configs` after `update_for_single_run` (D-02, resolved in 2026-04 and not done) and make the setter the only mutation path with a name that says so (`add_runtime_config`). Retire the DataFrame ensemble manager that no template uses.

### Rich Hickey — Simplicity
**Strengths.** `FetchContext`, `CacheProvenance`, `EnsembleContext`, `PredictionMetadata` are values: frozen, named, passed. The wire header is built as data and serialised once.
**Weaknesses.** `timestamp` is complected with three meanings (construction time, artifact time, log-generation time) living under one key (C-350, C-371). `target` means both a prediction column and a `model`/`ensemble` unit type. `prediction_format` complects on-disk layout, in-memory type and which stage branch runs. `self.__class__.__name__` as a type tag complects identity with behaviour. The `_ViewsDataset` hierarchy encodes a value (`SpatialLevel`) as a class axis (D-33). `use_weights` + `weights` is two keys for one concept and their interaction is undefined (C-363).
**Improvements.** Name the three timestamps (`artifact_stamp`, `run_started_at`, `log_written_at`) and let only the first name files. Replace the class-name test with the `target` value the subclass already sets.

### Kent Beck — Test-driven development
**Strengths.** 2,986 tests in 130 s with no failures. The guard idiom (AST over source, derived scopes) is unusual and effective where it is aimed; the conformance checks against sibling repos' fixtures are a genuine cross-repo seam. Strict xfails that flip when a story lands are a good expiry mechanism.
**Weaknesses.** Nineteen files replace modules in `sys.modules` with MagicMock before import; those tests cannot tell when the mocked boundary changes shape (C-338's thesis). Eight falsification files cannot fail or assert nothing (C-368). Five dataloader suites skip without viewser, the reporting-stage suites skip without views-reporting, and the minimal CI job excludes every `test_falsification_*` file — so the local run and the two CI jobs are three different suites. No conftest fixture reaches more than four files; each suite builds its own stubs, which is why the stubs drift (C-338). `tests/test_falsification_nothing_is_blocked_on_us.py` is untracked (C-374).
**Improvements.** One shared two-member ensemble fixture with real frames on tmp_path, used by all three manager suites. Delete the eight vacuous guards. Decide whether the minimal job should run the falsification files or the files should stop being tests.

### The Maintainer — Sufficiency
**Verdict: not done, but enterable — and most of the eight seats' findings should not be acted on.** A stranger can enter this code: the module docstrings that exist are long and honest, the ADRs are findable, and the register tells you where the bodies are (it is, in fact, the best map of the system; the 46 % docstring rate is the weak spot, not the governance). What makes the scope not done is a short list of silent-wrong-output paths that a maintainer would want closed before relying on the ensemble evaluation and the weighted pool: C-362, C-363, C-364, and the template no-op C-375. Everything else is either already registered with a trigger or is a shape complaint.

**Findings judged not worth acting on now:** the eleven-site wandb lifecycle duplication (stable, understood, D-06 said defer); splitting `files/utils.py` (its hub-ness is an inconvenience, not a defect); `DataFetchStrategy` (delete it in passing when `dataloaders.py` is next touched, not as a task); the class-name dispatch in `model_path.py` (C-348 exists; fixing it alone changes nothing a user sees); `LoggingModule`'s process-wide `dictConfig` (every consumer wants exactly that); `__activate_reconciliation` hard-coded True (cosmetic); the empty `ensemble_aggregator/` directory (delete it in any commit, do not track it); the domain-layer-without-consumer complaint (S-05/S-06 are tracked stories; a new ADR will not move them). The DF/PF `concat` semantic difference is documented in both places and the DF tier is retiring; do not unify.

## 5. Long-term regret test

1. **Two prediction tiers for two more years.** Every seam (savers, loaders, ensembles, sniffers, adapters, CICs) exists twice; each new feature lands on one tier and the other drifts (C-176, C-339, C-352). Painful at every release; prevented by a dated retirement for `prediction_format: dataframe` with a refusing window (ADR-062's shape), not by more parity guards.
2. **Un-versioned on-disk layouts.** `y_pred.npy` + `identifiers.npz` without a level or version tag, MetricFrames without run identity in the path, parquet names carrying a timestamp whose source is a convention. Painful the first time two runs of one model must coexist, or a reader must reject a stale artifact (C-184, C-347, C-362). Prevented by a run manifest at the run root — C-347's remedy, already built for the external store.
3. **The facade as inheritance contract.** Engines subclass a 2,200-line class and learn its conventions from a template that is itself wrong (C-375). Painful every time an engine author is onboarded. Prevented by making `IDataSource`-style Protocols the contract and the facade an implementation detail.
4. **Guards that cannot fail accumulate.** 46 guard files now, eight vacuous (C-368), and the author of a guard tests it with the model that missed the defect (Cluster L). Painful when a green build is cited as evidence in a release gate. Prevented by `falsify guard` as a gate (ship-it step 5.5), which exists; the regret is in the guards written before it did.
5. **Governance prose outgrowing the code it describes.** Ratio 1.35 today; the register header alone is a changelog. Painful for the newcomer the Maintainer seat represents. Prevented by moving release lessons into the guide (Cluster M's keystone) and keeping the register's header to one line per date.

## 6. Engineering recommendation

Do four narrow things, in this order, before any structural work: (1) make the evaluation stage raise on missing actuals and put run identity in the MetricFrame path (C-362); (2) make the weights refusal reachable and sniff `weights` (C-363); (3) fix the template's timestamp assignment and make the facade perform the copy-back itself (C-375, closing C-350's convention); (4) measure whether any production ensemble output contains `_ViewsDataset`-filled cells, then decide C-364. Then delete the eight vacuous guards and the untracked test (C-368, C-374). Defer every decomposition (C-01, C-36, C-221, C-353) behind the DataFrame-tier retirement, which removes half of each of them for free.
